# Архитектура

## Конвейер

```
                        общий для мух и людей
  ┌──────────────────────────────────────────────────────────┐
  │ фото / рендер → канонический кадр → нормализация яркости  │
  │              → гекса-решётка 721 колонка                  │
  │              → контраст, каналы ON и OFF                  │
  └──────────────────────────────────────────────────────────┘
                              ↓
        flyvis: 65 типов клеток оптической доли, веса заморожены
                              ↓
        нейроны FlyWire тех же типов внутри оптической доли
                              ↓
        связи FlyWire → проекционные нейроны → центральный мозг
                        LIF, веса заморожены
                              ↓
                частоты спайков по временным окнам
                              ↓
                  обучаемый readout (Ridge / PLS / MLP)
                              ↓
        Fly Beauty Score → перцентиль по референсу → PSL → тир → роаст
```

Идея — reservoir computing: настоящая мушиная схема используется как
замороженный резервуар, учится только выход.

Про стыковку flyvis с FlyWire: она делается **не** через проекционные нейроны, а
вливанием в нейроны оптической доли тех же типов. Почему именно так, с цифрами —
в `docs/SCIENCE.md`.

## Модули

| Путь | Что делает |
|---|---|
| `config.py` | загрузка и валидация YAML в pydantic-модели |
| `cli.py` | единый вход `flymog <command>` на typer |
| `data/connectome.py` | единый формат коннектома, подграфы, контрольная перестановка |
| `data/download.py` | загрузка данных, инструкции для ручной, синтетический суррогат |
| `vision/hexgrid.py` | гекса-решётка, сэмплирование, мозаика для карточки |
| `vision/encoder.py` | изображение → каналы ON и OFF, детерминизм |
| `vision/flyvis_frontend.py` | обёртка над flyvis, списки типов клеток |
| `sim/backends.py` | разреженное умножение: CSR и gather, выбор устройства |
| `sim/lif.py` | векторизованный LIF, батч по изображениям |
| `probes/` | команды разведки M0 и сборка отчёта |

Каталоги `render/`, `beauty/`, `readout/`, `calibrate/`, `scoring/`, `content/`,
`bot/` созданы под майлстоуны M1–M3 и пока пусты.

## Ключевые решения и почему

**Два backend'а для разреженного умножения.** `CsrBackend` на `torch.sparse_csr`
быстр там, где есть разреженное ядро. `GatherBackend` на `index_add_` не требует
разреженных ядер вообще, что важно на MPS. На CPU измерено: CSR примерно в
5 раз быстрее gather, поэтому `auto` выбирает CSR везде, кроме MPS.

**Состояние `[N, B]`, а не `[B, N]`.** Связи применяются как `W @ spikes`, и
такая раскладка даёт один матмул на шаг для всего батча. Независимость элементов
батча покрыта тестом: фотографии разных людей не должны влиять друг на друга.

**Кольцевой буфер задержек.** Синаптическая задержка около 1.8 мс — это
несколько шагов при `dt` 0.2 мс. Буфер фиксированной длины дешевле, чем очередь
событий, и не зависит от плотности спайков.

**Точное интегрирование за шаг.** Мембрана и синаптический ток обновляются через
`exp(-dt/tau)`, а не явным Эйлером. Это позволяет проверять симулятор против
аналитической частоты одиночного нейрона, что и делает тест.

**Детерминизм через хэш изображения.** Seed выводится из хэша уже
предобработанного кадра, поэтому один и тот же файл всегда даёт один и тот же
скор. Проверяется тестом.

**Суррогат коннектома.** Среда разработки не имеет доступа к хостам с настоящими
данными, поэтому есть генератор графа того же масштаба с тяжёлыми хвостами
степеней. Он помечен `is_surrogate`, и каждый probe, работающий на нём, печатает
предупреждение. Имена типов клеток начинаются с `SURROGATE_`, чтобы их нельзя
было перепутать с настоящими.

## Конфигурация

Всё в `configs/*.yaml`, разбирается в pydantic-модели, поэтому опечатка падает на
старте, а не превращается в молчаливое значение по умолчанию.

Параметры LIF помечены `TODO(verify)` и не сверены с первоисточником. На это
есть тест: он упадёт, если пометку снимут, не заменив её проверкой.

## Производительность

Измерения на CPU в `docs/M0_REPORT.md`. Лестница ускорения из ТЗ, в порядке
применения: `fp16` где безопасно, больший `dt` или более короткое окно, обрезка
до подграфа за k хопов, подмножество оптических долей и выходных нейронов.

По обрезке уже есть предупреждение: на суррогате она не дала экономии, потому что
у графа маленький диаметр. Проверка эквивалентности встроена и требует
корреляции частот не ниже 0.99.
