# Что сделать тебе — пошагово

Инструкция на один проход. Всё, что можно было сделать без твоей машины, уже
сделано и лежит в ветке `claude/flymog-telegram-bot-plan-agfqu9`. Здесь то, что
физически требует твоего железа и твоих прав.

Нужно примерно **6 ГБ диска** и 20–40 минут, из них большая часть — ожидание
загрузок и замеров.

Обозначения: команды даны для macOS и Linux. Для Windows в PowerShell замени
`.venv/bin/flymog` на `.venv\Scripts\flymog.exe`, а `\` в конце строки — на
` (обратный апостроф)`.

---

## Шаг 1. Проверь, что есть git, Python и uv

```bash
git --version
python3 --version
```

Нужен **Python 3.11 или 3.12**. Не 3.13: верхнюю границу задаёт `flyvis`, а он
у нас основной зрительный путь.

Если `uv` не стоит:

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows PowerShell
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

## Шаг 4. Скачай данные коннектома

Два клона и копирование. Zenodo не нужен, всё берётся через git.

```bash
mkdir -p data/connectome

# Связи FlyWire v783 и порядок нейронов (~370 МБ)
git clone --depth 1 https://github.com/philshiu/Drosophila_brain_model.git /tmp/dbm
cp /tmp/dbm/Connectivity_783.parquet data/connectome/
cp /tmp/dbm/Completeness_783.csv     data/connectome/

# Аннотации: типы клеток, суперклассы, координаты (~32 МБ)
git clone --depth 1 https://github.com/flyconnectome/flywire_annotations.git /tmp/fwa
cp /tmp/fwa/supplemental_files/Supplemental_file1_neuron_annotations.tsv \
   data/connectome/flywire_neurons.tsv
```

На Windows вместо `/tmp/dbm` возьми любую временную папку, например
`$env:TEMP\dbm`.

Проверь:

```bash
.venv/bin/flymog fetch-data
```

В колонке «present locally» должно быть `yes` у `flywire_connectivity` и
`flywire_annotations`. У `flyvis_pretrained` пока `no` — это следующий шаг.

## Шаг 5. Поставь flyvis и скачай его веса

Пакет тяжёлый, ставится отдельно:

```bash
uv pip install --python .venv/bin/python -e ".[flyvis]"
```

Веса лежат на Google Drive, поэтому из моего окружения они были недоступны.
У тебя должно получиться:

```bash
.venv/bin/flyvis download-pretrained --skip_large_files
```

`--skip_large_files` пропускает архив с UMAP и кластеризацией, он нам не нужен.

Проверь, что веса встали:

```bash
.venv/bin/python -c "from flymog.vision.flyvis_frontend import flyvis_availability; print(flyvis_availability().as_dict())"
```

В выводе должно быть `'pretrained_available': True`. Если `False` — пришли мне
вывод, посмотрим, куда оно положило файлы.

## Шаг 6. Сними замеры на своём железе

Это главное, ради чего всё затевалось. Три команды, каждая пишет JSON в
`artifacts/m0/`.

### 6.1. Железо

```bash
.venv/bin/flymog probe-env
```

Быстро. Покажет, видит ли torch твои 18 ГБ: `cuda_available: true` для NVIDIA
или `mps_available: true` для Mac. **Если оба `false`** — torch встал в
CPU-сборке, напиши мне, какая у тебя ОС и видеокарта, подберём правильную
установку.

### 6.2. Скорость

```bash
.venv/bin/flymog bench-sim --batch 32 --check-pruning --k-hops 5
```

Несколько минут. Гоняет оба бэкенда на всех сочетаниях `dt` и окна, потом
проверяет обрезку графа. На моём CPU вышло 1.32 изобр./с при батче 32, окне
200 мс и `dt` 0.2 мс — у тебя на ускорителе должно быть заметно быстрее.

### 6.3. Режим работы сети

```bash
.venv/bin/flymog sweep-regime --batch 512
```

Долго, это 16 прогонов по полному коннектому. **Батч 512 взят не с потолка:**
я замерил, что один элемент батча стоит около 7 МБ плюс 1.7 ГБ на сам
коннектом, так что в 18 ГБ он помещается с запасом. Батч важен потому, что
критерий выбора (participation ratio) ограничен сверху числом образцов минус
один, и при малом батче он упирается в потолок и перестаёт что-либо различать.
На 64 он был вырожден.

Если увидишь ошибку нехватки памяти — снижай до 256, потом до 128, и скажи мне,
на чём остановилось.

Файлы не содержат ничего личного: это характеристики машины и числа замеров.

## Шаг 9. Два решения, которые могу принять только ты

### 9.1. Лицензия данных FlyWire — решить до M1

Это не формальность. Если данные под некоммерческой лицензией, то бот, в
котором когда-либо появится донат, платная функция или реклама, нарушает её.

Что нужно сделать: открыть у себя (у меня эти хосты закрыты)
<https://codex.flywire.ai/faq> и запись FlyWire на Zenodo, найти точную
формулировку лицензии и прислать её мне. Я запишу её дословно со ссылкой в
`docs/DATA_LICENSES.md`.

Отдельно учти: репозиторий Shiu под MIT, но **MIT покрывает его код, а не
данные FlyWire, которые он перераспространяет**.

### 9.2. Что делать, если коннектом окажется бесполезен

В развёртке режима обнаружилось, что средняя частота почти не меняется при
росте рекуррентного масштаба весов с 0.001 до 0.1. То есть в выбранной рабочей
точке резервуар в основном повторяет вход, а собственная динамика коннектома
вносит мало.

В M1 обязательная абляция «настоящий коннектом против перемешанной сети с теми
же степенями» это проверит. Если разницы не окажется, у нас два пути:

1. Оставить как есть и честно написать в README, что коннектом — декорация.
   Бот от этого не перестаёт быть смешным.
2. Искать рабочую точку, где рекуррентность действительно влияет, ценой
   времени и, возможно, скорости.

Скажи заранее, какой вариант тебе ближе, чтобы я не останавливался посреди M1.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `flymog: command not found` | зови по полному пути `.venv/bin/flymog` |
| `pytest` красный | пришли вывод, дальше не иди |
| `probe-env` показывает cuda и mps `false` | torch в CPU-сборке, напиши ОС и видеокарту |
| `ConnectomeDataMissing` | вернись к шагу 4, команда сама печатает нужные пути |
| `flyvis download-pretrained` падает | пришли вывод, там Google Drive и он бывает капризен |
| Нехватка памяти в `sweep-regime` | снижай `--batch` вдвое и скажи, на чём остановилось |
| `bench-sim` идёт очень долго | это нормально на CPU; на ускорителе должно быть в разы быстрее |
